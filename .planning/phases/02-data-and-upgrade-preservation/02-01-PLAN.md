## Phase Goal

**As a** site owner, **I want to** update GigPress without losing or corrupting existing records, relationships, settings, or show-management behavior, **so that** my established site remains usable after the update.

<objective>
Prove the phase architecture with one production-quality vertical upgrade path: a populated reconstructed 1.4 database reaches the current 1.6 state, remains unchanged on repeat loads, and stops safely when any required step cannot be proven.

Purpose: Establish the safe coordinator, bootstrap gate, durable retry contract, and disposable fixture harness that every remaining source version and mutation workflow can extend.
Output: A representative data-safe upgrade, failure/retry behavior, authorized notice, mutation gate, and one focused container command that verifies the complete path.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Plugin bootstrap to legacy database | Repository upgrade code reads and mutates prefix-aware site-owned tables/options/posts whose historical state is untrusted. |
| Upgrade state to normal plugin surface | Coordinator status controls whether mutation-dependent hooks and handlers may register. |
| Compatibility fixture to disposable database | Reconstructed test data may mutate only the unique Compose database created by the runner. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Tampering | `admin/db.php` upgrade coordinator | high | mitigate | Journal intent and exact IDs, treat strict `$wpdb` errors as failure, verify postconditions, and write/read back the final marker only after every invariant passes. |
| T-02-02 | Elevation of privilege | `gigpress.php` blocked-upgrade branch | high | mitigate | Register no migration-dependent mutation surface while blocked and show the escaped notice only to users with `activate_plugins`. |
| T-02-03 | Information disclosure | `gigpress_db_upgrade_notice()` | medium | mitigate | Emit only stable failure codes and recovery guidance; omit SQL, row values, table contents, credentials, and exception dumps. |
| T-02-04 | Tampering | `tests/compat/run.sh` database target | high | mitigate | Reuse the unique Compose project/volume contract, reject external database targets, and perform all fixture mutations inside the disposable WordPress/MariaDB cell. |
| T-02-SC | Tampering | npm/pip/cargo installs | high | mitigate | This plan adds no package-manager install; if execution introduces one, halt until the package-legitimacy audit and required human gate are present. |
