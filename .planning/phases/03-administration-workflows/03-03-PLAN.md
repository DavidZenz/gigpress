NEW POST protocol keeps show_id[] explicit and gpaction=delete with trash_stage=preview|confirm|cancel. Preview verifies capability/nonce/readiness and produces a server-owned intent: random token, current user, exact deduplicated ordered positive IDs and normalized return state, stored in a short-lived WordPress transient (15 minutes). Confirm posts token, exact same IDs, stage-specific nonce and return state; capability/nonce/readiness and server intent ownership/expiry/ID equality are checked before any row write. Return state is read from the stored validated intent. Cancel consumes only the current user's matching intent and returns to the stored normalized list without show mutation. GET may open an individual preview with nonce, but never confirms or writes; the row Trash control uses a POST preview button to keep the primary flow server-rendered/no-JS. No request can widen IDs from filters/header/current page.
The NEW individual submit button uses trash_single_id=<clicked row ID>; only that explicit button value supplies the single preview selection, irrespective of simultaneously checked bulk boxes. Bulk submit omits trash_single_id and uses show_id[] only. Validate the single value without coercion and convert it to the same one-element intent; confirmation then carries show_id[] under the common protocol. Header checkboxes have no selection IDs and may only check visible named row boxes as a browser enhancement.
Per-ID outcome fields: show_id, result changed|already_trashed|missing|stale|failed, reason and safe available edit/list link. changed_ids alone drive the Undo link. Preserve status-based trash and existing restore semantics/identity. Case request adapter must set GET/POST/REQUEST separately and REQUEST_METHOD deliberately; the old helper that fills both GET and POST cannot establish confirmation method security.
